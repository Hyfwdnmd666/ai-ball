# ai-ball

一个**不抢焦点**的悬浮球：飘在屏幕最上层，流式显示「内心独白」，还能跟你对话。

**"不抢焦点"是它的全部意义** —— 点它不会打断你正在全屏玩的游戏。
（这条已经实测验证过，见 [下面的证据](#-已验证点它真的不抢焦点)。）

---

## 30 秒上手

```bat
双击 start.bat
```

完事。球会出现在屏幕左上角。**右键它**就是控制面板（大小 / 图片 / 主题 / 退出）。
面板底部有输入框，可以跟它说话。

> **默认是"回声大脑"**：你说什么它就复述什么，只证明管道通了，**不花钱**。

> **想让 AI 自己说话？** 球是哑的 —— 它只认文件，不关心是谁写的。
> 所以任何进程都能当它的大脑：[`dsh-ai-ball`](https://github.com/Hyfwdnmd666/dsh-ai-ball)
> 就是让 DeepSeek Harness 里的 agent 通过这颗球说话、做表情、听你打字的插件。
> 你自己写一个也行，接口就是 [那几个文件](EXTENDING.md)。

### 想让它真的回话

1. 去 `platform.deepseek.com` 建一个 API key
2. 编辑 `brain.json`：把 `"brain"` 改成 `"api"`，把 key 贴进 `"api_key"`
3. 再双击 `start.bat`

`start.bat` 会先自检脑子，**没配好会当场警告你** —— 免得你打了字、却没人回，
还分不清是没配好还是球坏了。（球照样会起来，自检只是让你看见问题。）

> 换别家（OpenAI / 月之暗面 / 本地 Ollama）只要改 `brain.json` 里的
> `base_url` 和 `model`，只要是 OpenAI 兼容接口就行。**球一个字都不用改。**

### 没装 Python？

要 **Python 3.10+**（自带 tkinter）。Windows 上从 python.org 装，
安装时勾上 **"Add python to PATH"**。`Pillow` 可选 —— 有它球更平滑，没有也能跑。

> **`start.bat` 找不到 Python 怎么办？**
> 它会依次试：`%AIBALL_PYTHON%` → PATH 上的 `python` → `py` 启动器 → 常见安装位置。
> 都找不到就给你一句人话。你的 Python 在奇怪的地方就显式指定：
>
> ```bat
> setx AIBALL_PYTHON "C:\path\to\python.exe"
> ```
>
> 然后**开一个新的终端**再跑 `start.bat`（`setx` 不影响已经开着的窗口）。
>
> 注意它会**真的去试**每个候选（跑一次 `import tkinter`），不是信 `where` ——
> 有些 Windows 上 PATH 里的 `python` 是微软商店的占位符，一跑就报错。

## 它是什么

```
        我 (AI)                     ball.py                   你
          │                          │                        │
          │  写 monologue.log  ────► │  流式飘出来  ────────► │ 看
          │                          │                        │
```

**球是哑的。** 它不 import 游戏、不知道 AI、不知道管道。
它只做一件事：**tail 一个文本文件，把新内容一句句吐出来。**

所以接真管道、接游戏的时候，**这个文件一行都不用改**。

## 怎么跑

```bash
cd ai-ball

# 1. 起球（会飘在屏幕左上角）
python ball.py

# 2. 另开一个终端，喂字
python feed.py --demo                 # 播放内置样本（模拟真人语速）
python feed.py "我操，三发实弹还没出"    # 追加一句
python feed.py --reset                # 清空（球会跟着清屏）
echo "从管道来的" | python feed.py --stdin
```

> `feed.py` 在真管道接好之前，就是「我」的手动替身。

| **拖动球** | 移动整个窗口 | 不要 |

## 对话功能：面板不只是独白，还能回话

面板底部有个输入框。**点它才临时借焦点**，回车发送、Esc 取消，**两种情况都立刻把焦点还回去**：

```python
def _entry_grab(self):                              # 点输入框
    self._prev_fg = user32.GetForegroundWindow()    # 记住原来是谁在前台
    self._set_noactivate(False)                     # 临时允许激活
    user32.SetForegroundWindow(self._hwnd)

def _release_focus(self):                           # 回车 / Esc
    self._set_noactivate(True)                      # 恢复「绝不激活」
    user32.SetForegroundWindow(self._prev_fg)       # 焦点还给它
```

**默认状态下一个字都打不进去** —— 只有你亲手点了输入框，那一小段时间窗口才可激活。

两边的消息在同一条流里，靠颜色分：

| | 来源 | 显示方式 |
|---|---|---|
| **我** | `monologue.log` | 普通色，**逐字流式**（像在说话） |
| **你** | `input.log` | 强调色（深色下浅蓝），**立刻出现**（不打字机） |

你说的话只是**写进 `input.log`**，球不关心谁去读它：

- 手动模拟：`python feed.py --as you "你在干嘛"`
- 接真 AI：让某个东西「轮询 `input.log` → 想 → 写 `monologue.log`」就行

> ⚠️ **球本身不会思考。** 你打的字会安静地进 `input.log`，但**球不会回你** ——
> 回话是另一个进程（`brain.py`）的事，见下一节。

## 让球真的会回话：`brain.py`

```
input.log  ──轮询──►  brain.py  ──调模型──►  monologue.log
（你说的话）                                  （独白 / 回话）
```

**球完全不知道有这个进程** —— 它只认文件。
所以换大脑、以后接游戏状态，**都不用改球一行代码**。

### 两种大脑

```bash
python brain.py --brain echo     # 假大脑：把你说的话原样复述，只验证管道，不花钱
python brain.py --brain api      # 真大脑：需要一个 key
```

**先用 `echo` 确认管道通，再换 `api`。**

### key 从哪来（按优先级）

1. `--api-key sk-xxx`
2. 环境变量 `DEEPSEEK_API_KEY` / `OPENAI_API_KEY` / `MOONSHOT_API_KEY`
3. `brain.json` 里的 `"api_key"`

默认走 DeepSeek（`https://api.deepseek.com` + `deepseek-chat`）。
换别家就改 `brain.json` 的 `base_url` 和 `model` —— 只要是 **OpenAI 兼容**的 `/chat/completions` 就行。

> 别把 key 贴在聊天里。写进 `brain.json` 或设成环境变量。

### 人格写在 `persona.md`，不用改代码

那个文件就是「他是谁」：简体中文、口语、短句、**会算错会嘴硬**、
**禁工具**（不许列算式和期望值）、不限话量……

想改成别的性格，改那个文件就行。

### 以后接游戏状态：往 `context.md` 写

`brain.py` 每次请求前会读一遍 `context.md`（如果存在），当作「当前局势」拼进系统提示。

**你只要往那个文件里写状态**，`brain.py` 和球都不用动。这就是留给游戏接口的缝。

### 会话历史

存在 `brain_history.json`，重启不掉。只保留最近 `history_turns` 轮（默认 12）——
免得请求越滚越贵。

## 让它出声：`voice.py`

`brain.py` 是**脑**，`voice.py` 是**嗓子**。它和 `brain.py` 是同一个模式：**一个独立进程，
只认文件** —— 盯 `monologue.log`，把新说的话念出来。

**嗓子跟着球一起起、一起关。** `ball.py` 启动时 `Popen` 一个 `voice.py`，退出时
`terminate` 它 —— 所以**任何**启动球的方式都带声音：双击 `start.bat`、直接 `python ball.py`、
agent 通过插件拉起球，三条路一样。

（`start.bat` **不**再单独起嗓子 —— 那会变成两个进程念同一份日志，一前一后。）

起不来也绝不拖累球：球是主体，嗓子是配件。不想听就关掉：

```json
{ "voice": { "enabled": false } }
```

手动用：

```bat
python voice.py            :: 单独跑一个嗓子（球没在跑也行）
python voice.py --pick     :: 交互式挑音色（列出来 → 试听 → 存下来）
python voice.py --test     :: 念一句验一下
python voice.py --list     :: 看当前后端和音色
```

### 后端：为什么默认用 MiniMax，而不是 Windows 自带

Windows 自带的 SAPI 本来是零依赖的首选。但这台机器的语音引擎是坏的：
中文引擎数据目录不存在（注册表指到 `Speech_OneCore\...\M2052Huihui`，实际只有 `M2052Hongyu`），
英文数据在但引擎照样拒绝。所以默认走 **MiniMax 在线语音**：

- **`audio_setting.format` 支持 `wav`** —— 播放因此零依赖：`winsound` 直接吃 WAV，
  不需要解码器、不需要 `mpv`、不需要装任何音频库
- **`speech-2.8` 系列支持语气词标签** `(sighs)` `(laughs)` `(snorts)` `(gasp)` ——
  这是真的情绪音效，不是念稿
- 有个 `emotion` 参数（happy/sad/angry/…）和 `speed`/`pitch`/`vol`

配置在 `voice.json`，key 放 `_minimax-key.txt`（一行；`#` 开头的说明行会被跳过）。
国内版端点是 `https://api.minimaxi.com`，**国际版 `api.minimax.io` 的 key 不通用** ——
用错了会得到 `2049 invalid api key`。

### 三个踩过的坑

**① `winsound` 不允许「内存 + 异步」同时用。**

```
SND_MEMORY | SND_ASYNC  →  Cannot play asynchronously from memory
```

异步播放必须走文件。所以合成结果先落盘到 `.speak-<pid>.wav` 再播；
`--test` / `--say` 那种阻塞路径才可以吃内存。

**② 新的一句必须打断旧的。**

真人不会把上一句念完才开始下一句。合成要 1~2 秒，不打断的话排队会越拖越远，
最后你在听三十秒前的话。`PlaySound(None, 0)` 掐断，然后合成新的一句。

**③ 语气词标签是半角括号，动作描写是全角括号。**

`clean_for_speech` 只删**全角**（……），保留**半角** (...) —— 因为 `(sighs)` 是标签，
（小声）是动作描写。中文习惯用全角写动作，正好能区分开。

### 熔断

连续 5 句没念出来就停下，并说清楚先跑 `--test`。key 过期 / 断网 / 引擎坏了的时候，
一直重试只会把日志刷满，而且球看起来"在说话"其实一声不吭 —— 那比直接停掉更难查。

## 右键菜单是自绘的，但长得像 Windows 原生的

**深色底**、系统字体、整行可点、悬停高亮、分隔线、浅红退出 —— Windows 11 深色右键菜单的样子。

但它**不是** `tk.Menu`。原生菜单会短暂成为前台窗口，游戏会因此失焦暂停。
这里其实是**长在球窗口里的一个 Canvas** —— 同一个 `WS_EX_NOACTIVATE` 窗口，
所以点它上面的项目**同样不激活窗口**。

## 「有背景」这件事：卡片显示时整窗实心

```python
def _effective_alpha(self):
    if self.menu_open or self.panel_visible:
        return 1.0                       # 有卡片 → 实心
    return float(self.cfg["ball"]["alpha"])   # 光一颗球 → 用配置值
```

`alpha` 是**整窗属性**，没办法只给面板或菜单设置。而半透明的卡片**看着不像有背景** ——
底下的窗口会透出来，一眼就脏。所以只要有卡片在显示，整窗一律不透明。

代价：**「不透明度」只在「光一颗球」的状态下看得出效果**。
真想拆开的话，得把球和卡片做成两个窗口（目前没做）。

### 退出是故意不放在手势上的

右键在所有人脑子里都是「菜单 / 选项」，挂成「退出」必然误触，而且没有提示。
破坏性动作必须走一条明确的、看得见的路 —— 现在它在控制面板最底下，红色的，还会问你一句。

**注意：球永远拿不到键盘焦点**（这是故意的），所以调参一个快捷键都没有 ——
全是鼠标手势，修饰键靠 `GetAsyncKeyState` 全局读，**不碰焦点**。

**只有两个地方会短暂抢焦点**，而且都是你主动点出来的：

| 什么时候 | 为什么躲不掉 |
|---|---|
| **点输入框打字** | 打字必须有键盘焦点。回车/Esc（或点走）立刻还回去 |
| **「退出」确认框 / 「选图片…」文件选择框** | 系统对话框，Tk 没法让它们不激活 |

除此之外 —— 点球、拖球、滚轮、右键菜单、控制面板 —— **一次焦点都不碰**。
（注意上面那两个**不是**什么"设置面板"：独立设置窗口早就去掉了，
所有参数现在都在右键菜单里。）

## 控制面板（右键菜单）

**只有一个界面**，两层，同一套 Windows 原生样式：

```
┌──────────────────────┐   ┌──────────────────────┐
│ 独白面板        显示 │   │ 主题            深色 │
│ 大小       112  − +  │   │ ──────────────────── │
│ 不透明度    92% − +  │   │ 字号        11  − +  │
│ 图片缩放  1.00  − +  │   │ 面板宽     430  − +  │
│ ──────────────────── │   │ 面板高     280  − +  │
│ 选图片…              │   │ 面板位置        右   │
│ 更多设置           › │──▶│ 间距        16  − +  │
│ ──────────────────── │   │ 内边距      12  − +  │
│ 退出 ai-ball         │   │ 行距         4  − +  │
└──────────────────────┘   │ 语速         4  − +  │
                           │ ──────────────────── │
                           │ 玻璃高光        关   │
                           │ 清除图片             │
                           │ ──────────────────── │
                           │ 恢复默认值           │
                           └──────────────────────┘
```

> 图里的数字是**某次运行时的实际配置**，不是出厂默认值 —— 默认值见下面
> [配置](#配置文件)一节（比如直径默认 88、语速默认 2）。

**高频项在主菜单，低频项在二级菜单。** 没有独立的设置窗口 ——
那东西打开是另一个风格，跟菜单完全两个样子，等于白做。

### 面板的两种调法

**① 直接拖** —— 面板右下角有个拖拽把手（三道斜线），拉着就能改尺寸，
不用进菜单点数字。**把手永远朝右下变大**，跟面板在哪一侧无关 ——
窗口原点是钉在球上的（球不动、窗口围着它变形），所以没有"要不要取反"这回事。
（早先按「在左/上就取反」写过，实测把手会跟鼠标反向、而且两倍速逃，已经去掉。）

**② 进菜单细调** —— 二级菜单里可以调：

| 项 | 范围 | 说明 |
|---|---|---|
| 字号 | 8 ~ 22 | |
| 面板宽 / 高 | 200~900 / 100~720 | |
| **面板位置** | 右 → 下 → 左 → 上 | 点一下循环。球会跟着换到另一侧 |
| **间距** | 0 ~ 80 | 球和面板之间的缝 |
| **内边距** | 0 ~ 36 | 面板里文字到边框的距离 |
| **行距** | 0 ~ 24 | 独白行与行之间 |
| **语速** | 1 ~ 10 | 每次吐几个字（配合 `reveal_ms`） |

（另有 **主题 / 玻璃高光 / 清除图片 / 恢复默认值** 四项，不是数字。）

> **「玻璃高光」关掉之后，mood 照样看得见。** 图片球上那道边缘光是 mood 唯一的落点，
> 所以它由两张"票"共用：高光开着时按高光强度画，关掉时**只要 mood 有值就仍然画**。
> —— mood 是信息，高光是装饰；关装饰不该把信息一起关掉。

### 主题（内置浅色 / 深色，可扩展）

二级菜单最上面那项 **「主题」** 就是主题切换 —— **点一下循环一个**：
内置的 浅色 / 深色，以及 `themes.json` 里的自定义主题（见 [`EXTENDING.md`](EXTENDING.md)）
都在这个循环里。内置两套都是照着 **Windows 11 右键菜单**配的：

| | 深色 | 浅色 |
|---|---|---|
| 底 | `#1f1f1f` | `#f9f9f9` |
| 字 | `#ffffff` | `#1c1c1c` |
| 值 | `#a6a6a6` | `#6b6b6b` |
| 悬停 | `#333333` | `#eaeaea` |
| 退出 | `#ff99a4` | `#c42b1c` |

**菜单和独白面板共用同一套色**，切主题一起换。存在 `config.json` 的 `ui.theme` 里。

> ⚠️ **面板的底色 / 字色由主题决定，手改 `config.json` 里的 `panel.bg` / `panel.fg` 是没用的** ——
> 换主题时会被覆盖回去。想改配色就加一套主题，见 [`EXTENDING.md`](EXTENDING.md)。
>
> 「恢复默认值」会保留几样东西：**球的位置、球身图片、主题、文件路径** ——
> 它们是内容不是样式（重置后路径不跟着变，就会出现"cfg 说 monologue.log、
> 球还在 tail 老文件"这种鬼状态）。

## 文件协议

| 文件 | 谁写 | 说明 |
|---|---|---|
| `monologue.log` | 我 / `feed.py` | **「我」的独白**。追加；球按**字节**偏移读增量，逐字流式显示 |
| `input.log` | 你（输入框）/ `feed.py --as you` | **「你」说的话**。追加；球按行读，立刻插入 |
| `status.json` | 任何东西 | **状态通道**：mood + 心跳，**覆盖写** |
| `themes.json` | 你 | 自定义主题（从 `themes.example.json` 复制） |
| `config.json` | 控制面板 / 你手改 | 样式与参数（运行期状态，不进仓库） |
| `state.json` | 球（自动） | **只存**窗口位置和面板开合这两个高频项 |
| `demo_monologue.txt` | — | 样本独白，`feed.py --demo` 用 |

> **启动行为**：已有的日志会**一次性铺上**，不重播动画。
> 「说话」只发生在启动之后写入的新内容上 —— 否则每次重启都像在放录像带。

**重置规则**：如果 `monologue.log` 变短了（被清空或重写），球会自动清屏并从头读。
所以 `feed.py --reset` 是安全的。

## 配置（`config.json`）

**默认值在 `ball.py` 的 `DEFAULTS` 里**，下面这份是照着它写的：

```jsonc
{
  "ball": {
    "x": 60, "y": 60,           // 屏幕位置
    "diameter": 88,             // 球的直径
    "alpha": 0.92,              // 不透明度
    "color": "#0891b2",         // 球身
    "ring": "#a5f3fc",          // 安静时的环
    "ring_active": "#ffffff",   // 说话时的环
    "image": "",                // 球身图片（空 = 程序画的玻璃球）
    "image_gloss": true,        // 图片球上的玻璃高光
    "image_zoom": 1.0           // 图片放大（把脸框进圆里）
  },
  "ui": { "theme": "dark" },    // light / dark / themes.json 里自定义的名字
  "panel": {
    "visible": true,
    "width": 430, "height": 280,
    "gap": 16,                  // 球和面板之间的缝
    "side": "right",            // right / bottom / left / top（放不下会自动换边）
    "padding": 12, "line_spacing": 4,
    // bg / fg / border 由**主题**提供，手改这里没用（见上面「主题」一节）
    "font_family": "Microsoft YaHei UI",
    "font_size": 11
  },
  "stream": {
    "file": "monologue.log",    // 独白文件
    "poll_ms": 120,             // 多久看一次文件
    "reveal_ms": 40,            // 多久吐一次字
    "chars_per_tick": 2         // 每次吐几个字 → 一起控制「语速」
  },
  "chat":   { "input_file": "input.log" },
  "status": {
    "file": "status.json",      // 状态通道
    "poll_ms": 1000,            // 多久读一次
    "stale_s": 20               // 心跳超过这么久没更新 → 球变灰
  }

```

> `state.json` 只覆盖 **`ball.x` / `ball.y` / `panel.visible`** 这三项
> （`alpha` 存在 `config.json` 里，不受它影响）。想恢复默认位置就把 `state.json` 删掉。
>
> **`config.json` 本身是运行期状态，不进仓库**（见 `.gitignore`）——
> 控制面板会实时改写它。所以那个文件里出现什么值，取决于你上次怎么调的。

## 三个关键技术点

### 1. 不抢焦点（命根子）

```python
WS_EX_NOACTIVATE = 0x08000000
SetWindowLongW(hwnd, GWL_EXSTYLE, ex | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW)
```

窗口被点击但**从不激活**。所以游戏不会因为你看它一眼就失焦暂停。

### 2. 圆形靠色键，不靠形状

```python
MAGIC = "#010203"                                  # 近黑，**不是品红**
root.attributes("-transparentcolor", MAGIC)
```

这个颜色的像素**既完全透明、又鼠标穿透**。
球画在这个底色上（PIL 4 倍超采样再缩回来），于是得到一个平滑的圆，
**而且圆外的点击会直接穿到游戏里去** —— 不需要自己写命中测试。

> **键色必须选近黑，不能用品红/亮绿。** 色键是精确匹配，而抗锯齿的边缘像素是
> 「球色 × 键色」的混合 —— 匹配不上、抠不掉，就会在球周围留一圈键色毛边。
> 品红毛边在浅色背景上非常刺眼。球的边缘本来就是深色描边，键色选近黑，
> 那圈过渡就自然融进描边里，看不见了。

### 3. 拖动绑在画布上，不绑在 item 上

`tag_bind` 到 item 的话，鼠标一离开球，`<B1-Motion>` 就不再触发。
所以按下绑 item、拖动和松手绑 canvas。

---

### 4. 调参不靠键盘

球拿不到焦点，所以不可能有快捷键。修饰键改用 `GetAsyncKeyState` **全局读状态**：

```python
def _shift_down():
    return bool(user32.GetAsyncKeyState(0x10) & 0x8000)
```

这不影响任何窗口的焦点 —— 只是「看一眼 Shift 现在是不是按着」。

### 5. 必须声明 DPI 感知（否则整个界面都是糊的）

```python
ctypes.windll.shcore.SetProcessDpiAwareness(2)   # 建窗口之前调用
```

**不调用的话，在 125% / 150% 缩放的屏幕上，Windows 会把整个窗口当成位图拉伸。**
字全是虚的，球身图片也是糊的 —— 看起来就像「没做精细」。

这个进程默认是 DPI-unaware（`GetProcessDpiAwareness` 返回 0），所以这一行是必须的。
代价是：**窗口的物理尺寸 = 代码里写的尺寸**，在 125% 屏幕上看起来会比原来小一圈。

### 6. 菜单用的是「色键圆角」，不是画出来的圆角

`_round_rect` 是个平滑多边形，真正让它看起来是圆角的是那个**四角的 MAGIC 底色** ——
四角落在 MAGIC 上，被色键抠成透明，于是自然就是圆角。

## ✅ 已验证：**点它真的不抢焦点**

这是整套方案成立的前提。**已经用硬件 HID 实测过了**，不是理论推断。

判据是硬的 —— 点球会开关面板，所以**窗口宽度变化 = 确实点中了**：

```
球的布局: 方向=right 直径=112 面板=开   窗口(实测) 446x224   球心 (88,112)
移动到球心: 到位   实际 (90,112)
窗口宽 446 -> 90                       ← 点开了面板 = 确实点中了球
点击前前台: <你当时正在用的那个窗口>
点击后前台: <同一个窗口>                 ← 没变
[OK] 命中球，且焦点没变 —— 「不抢焦点」成立
```

`tools/foctest.py` 就是这个测试。**它不属于插件本体** ——
`ball.py` 一个串口都不碰，也不依赖任何硬件：

```bash
python tools/foctest.py          # 默认 COM5
python tools/foctest.py COM7     # 或指定串口
```

它唯一的存在理由是：**「不抢焦点」这件事必须实测**。而自动点击需要真实 HID ——
`SendInput` 的坐标空间跟别的进程对不上，我在这上面栽了两次。

**没有板子照样能测**：用自己的手点球，看记事本的光标闪不闪。**10 秒的事，而且同样可靠。**

### 过程中揪出的一个真 bug：**启动瞬间抢前台**

原来 `WS_EX_NOACTIVATE` 是在 `tk.Tk()` **建完窗口之后**才设的 ——
建窗那一下窗口就已经变成前台了。也就是说「不抢焦点」在**启动那一刻是破的**。

第一次跑测试时因此拿到了假结果（"点击前后台都是 ai-ball"，测试根本不算数）。
修法是：建窗之前先记住谁在前台，设完标志、窗口显示出来之后再把前台还回去。

**这条能说明为什么"必须实测"** —— 光读代码，`WS_EX_NOACTIVATE` 明明设上了，
看起来天衣无缝。

## 状态通道：`status.json`

留给别人的扩展点。**任何进程**往这个文件写一行，球就跟着变 ——
**覆盖写，不是追加**：

```json
{"alive": 1791746122, "mood": "nervous"}
```

> ⚠️ **一定要整份覆盖。** 追加第二行会让整个文件 JSON 解析失败 →
> 状态被**静默忽略**（球既不变灰也不报错，看着就像"没生效"）。
> 正确写法：写进临时文件再 `os.replace` 原子替换（`brain.py` 就是这么干的）。
>
> ⚠️ **如果 `brain.py` 在跑，`status.json` 是它每 3 秒重写一次的。**
> 你（或游戏 mod）写进去的 `mood` **会在 3 秒内被踩回 `idle`**。
> 想让你自己控制脸色，把 `brain.json` 里的 **`"write_mood"` 设成 `false`** ——
> 那样它只刷心跳，你的 `mood` 会被原样保留。

| 字段 | 作用 |
|---|---|
| `mood` | 球的边缘光换色：`thinking` 紫 / `nervous` 红 / `smug` 金 / `broken` 灰 |
| `alive` | unix 时间戳。超过 `stale_s`（默认 20 秒）没更新 → 球变灰 |
| `panel` + `panel_seq` | 显示 / 收起独白面板。**`panel` 是命令，`panel_seq` 是它的序号** |

> **`panel` 必须带 `panel_seq`，球只在序号变化时动一次。**
> 不带序号的 `panel` 一律不执行 —— 因为没法区分「你刚关掉」和「它一直这么说」，
> 照做就会变成跟你抢面板开关。详见 [`EXTENDING.md`](EXTENDING.md)。

**"球变灰"就是"脑子没了"** —— `brain.py` 每几秒写一次心跳，所以它被 `kill -9`
掉之后，球会自己发现，不用谁去通知。

球**不关心是谁写的** —— 游戏 mod、大脑进程、你手写，都一样。

## 已知限制 / TODO

- **PIL 是可选依赖**。没有 PIL 会退化成原生椭圆（有锯齿）。核心功能
  （流式、对话、菜单、mood 变色）都不受影响 —— mood / 心跳用球的描边颜色表示。
- **呼吸动画已关掉**（`BREATHING = False`）。静止的球更干净，也省 CPU；想要就改成 `True`。
- **窗口物理尺寸 = 代码尺寸**（已声明 DPI 感知），在 125% 屏幕上观感会比 100% 小一圈。
- **`-transparentcolor` 和 `-alpha` 在个别 Tk 版本上会互相顶掉**。如果球看着不是半透明的，把 `alpha` 调成 `1.0` 试一次，能确认是不是这个冲突。
- **没有 TTS**。声音是最强的活人信号，但它会带来语音包体积、依赖和授权问题 ——
  对一个希望别人随手就能跑起来的项目来说，这是**有意的取舍**，不是遗漏。
- **聊天历史没有时间戳**。重启后「我」和「你」的先后顺序可能对不上。
- **纯透明 PNG 当球身会变成「筛子」**：透明的地方会落成色键色，既透明又鼠标穿透。
  用不透明的方图。
- **面板只留最近 3000 行**（`MAX_TEXT_LINES`）。超出后最老的内容会被砍掉；
  启动时如果已有的日志超限，顶部会显示一行「……（更早的内容省略）」。
- **自动换边只在「放得下」时生效**。球贴屏幕边时面板/菜单会自动翻到对面
  （依次试 配置方向 → 正对面 → 剩下两个方向）。四个方向都放不下（比如面板比屏幕还大）
  才退回配置里那个方向，那时仍然会伸出屏幕。
- **`config.json` 是运行期状态，不是默认值**。默认值在 `ball.py` 的 `DEFAULTS` 里；
  `config.json` 由控制面板实时改写，所以它**不进仓库**（见 `.gitignore`）。
